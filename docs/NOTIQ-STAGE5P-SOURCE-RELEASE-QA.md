# NOTIQ Stage 5P-A — Source-only Windows QA packaging and release gates

## Baseline and intended scope (24 October 2026)
- Start from **5N-E feature branch** `feature/notiq-stage5ne-fullsong-stability`, after reading `docs/NOTIQ-STAGE5NE-LONGSONG-QA.md`. Stage 5N-E run #40086635944 was Windows CI PASS (21 native + 71 Web/MIDI). Work remains on independent `feature/notiq-stage5p-release-gates` branch, **no production merge or changes to main**.
- **Critical 5P risk fixed:** 5N-B through 5N-E packaged by downloading `NOTIQ-Stage5M-C-Resumable-Windows-Preview` from an October 2026 Actions run with a short artifact retention lifetime. Once its archive expired, further packaging would be unreproducible. The new workflow compiles both components from pinned Git source; **it does not download old Actions archives**.
- Current stage is an *internal QA preview*, not final release: user’s original requirement is to test the 2.74GB MuScriptor Large model on their Windows i5/16GB laptop, with 4–6 minute music and same-performance reference MIDI, before suggesting installation/download.

## Implemented
1. `.github/workflows/notiq-stage5p-source-windows.yml`: public-repository Windows runner checks out recursive source submodules including pinned `ThirdParty/muscriptor.cpp`; runs CPU/native/full-song/release-guard tests; detects genuine MSVC generator; builds C++ MuScriptor CLI from source (CPU-only), independently tests `--capabilities`, `--self-test` and a C++ checkpoint write/read `--self-test-checkpoint`; builds the entire Web React/TypeScript/MIDI stack and regression tests; downloads Electron package *dependencies*, but **no prior NOTIQ release artifacts**; stages `www`, compiled CLI, then packs Windows x64 with Electron 38 + electron-packager into a portable program.
2. `desktop-preview/release-audit.cjs`: hashes native CLI, Windows app EXE and Electron `app.asar` using streaming SHA256; validates x64 PE headers, 13 required ASAR runtime modules + compiled `www/index.html` and referenced assets, and ensures GGUF weights aren't embedded in the portable. Creates `NOTIQ-5P-INTEGRITY.json` **inside** the portable, with hashes and mandatory blockers. Status always **`QA_PREVIEW_ONLY`, `releaseApproved: false`**, even if source-build CI passes.
3. `desktop-preview/tests/release-audit-5p.test.cjs`: 5 regression cases: successful integrity check still not production approval; reject invalid x64 executable; reject missing runtime module; reject accidentally embedded GGUF; reject broken/empty Electron ASAR module.
4. `README-STAGE5P-QA.txt` in artifact communicates model weight absence, remaining real inference/F1/pedal QA and local data location.

- Compare current output vs same-performance human-aligned reference MIDI (note F1, onset/offset, false/extra notes), explicitly reject regression; listen A/B with edited velocity and CC64.
- QA signed/user-confirmed after real playback; **no autonomous release approval**, no false claim of true pedal recovery or studio-realistic piano timbre. No `main` merge without explicit user approval.
