## Legal choice and verified sources
1. [Vienna 4×22 Piano Corpus](https://datasets.mdw.ac.at/datasets/dataset/98ea25fa-2468-43ff-929b-3c926e163583): acoustic piano performances recorded in Vienna in 1999 with corresponding Bösendorfer MIDI; publisher **University of Music and Performing Arts Vienna**, attributed to **Werner Goebl**, DOI **10.21939/4X22**, published **CC BY 4.0**. The official audio distribution entry [Vienna 4×22 audio](https://datasets.mdw.ac.at/datasets/distribution/106a4eba-4ebe-424f-a284-0ede77de7d68) reports **audio.zip 1,295,130,820 bytes**. Source binary URL identified from the official download: `https://datasets.mdw.ac.at/media/content_files/8dec8d0a-c4da-4a96-b290-a3ba783c03ba.zip`. MIDI naming/format sourced from [CPJKU/vienna4x22](https://github.com/CPJKU/vienna4x22), CC BY 4.0.
2. MAESTRO dataset was assessed and **not selected** because the [official dataset license](https://magenta.withgoogle.com/datasets/maestro) is **CC BY-NC-SA 4.0**, with non-commercial restrictions. A third-party mirror marked MIT does not change the upstream data license.
3. Vienna is a set of **excerpts**, not necessarily 240–360-second uninterrupted pieces. The selector reads actual WAV headers and refuses to count recordings outside 4–6 minutes as full-song benchmarks. One genuine short Vienna performance may be used as `REAL_AUDIO_SHORT_SMOKE_ONLY` but it cannot satisfy the final 5P-B/5P-C release gate.
4. No synthesizing, looping, interpolation or splicing separate real pieces to manufacture a 4–6 minute recording. Never claim generic classical scores are from the same performance as the reference MIDI.

## Implementation
- `scripts/5pd/prepare_vienna.py`: bounded official archive downloader (byte count check), strict license attribution, WAV duration inspection and exact stem-matched raw MIDI retrieval from CC BY repository. Files are stored only on the ephemeral runner. Manifest stores SHA256 and actual duration. A paired sample outside 240–360s is honestly marked SHORT_REAL_SMOKE.
- `scripts/5pd/benchmark_real_piano.py`: actual native model execution (not a JS imitation) with required model SHA-256 `35a750fb1ab1e77195cdc2c0b9b4aeea2f4d59f11f729f02af9920c4854ef72e` and 2,739,142,176-byte pinned Large GGUF. Decodes original real WAV to 16 kHz mono IEEE Float32 using ffmpeg. Verifies audio duration. Executes genuine compiled MuScriptor CLI with chosen CPU thread count/checkpoint; samples real native PID RSS and CPU via psutil, never estimates memory from model filesize. Requires successful output JSON schema. Matches paired MIDI notes with exact pitch and onset ±100 ms, one-to-one, produces TP/FP/FN, raw precision/recall/F1 plus onset/offset MAE. Does **not** optimize MIDI alignment offset on the test reference; any offset must be predetermined and is reported. Excludes drums/non-piano. JSON contains only aggregate scores and SHA hashes: no raw notes, audio, personal names or source filesystem paths. Real measured output still says `release_approved:false`.
- `scripts/5pd/test_5pd.py`: artificial short fixture tests validate the scorer, output schema, audio framing and invalid sample gates. These fixtures are expressly **not** AI accuracy evidence.
- `.github/workflows/notiq-stage5pd-real-piano.yml`: auto-run cheap Windows Python benchmark tests on pushes. A separate expensive actual source-built Windows native + Large model + verified licensed Vienna audio job is intentionally restricted to an explicit `[5PD_RUN]` reviewed branch commit or manual workflow dispatch, to avoid multiple 2.74GB downloads on every code edit. CI uploads only a compact performance JSON (if an authentic run completed), never 1.3GB sound archive, model weights, raw MIDI or copied WAV.
