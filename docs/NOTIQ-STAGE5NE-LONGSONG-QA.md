Do not claim a real long-song inference PASS from synthetic audio or self-test.
- New observations are **only native process PID**; no fabricated percentage, no global system CPU masquerading as model CPU, no raw notes/WAV/upload.
- Tests include deterministic synthetic 240-second and 360-second WAV files to validate framing, size/length and progress diagnostics, *not* their conversion into correct notes.

## Implemented
1. `desktop-preview/full-song-health.cjs`: validates Float32 16kHz mono WAV framing against actual byte size and converts it to full-song duration; formats an honest watchdog status (90s no CLI/checkpoint activity = slow, 180s = no progress, without claiming frozen); reports native PID current/peak working set and CPU core equivalent, reporting unmeasured values as such. Warns at a **12 GiB measured process peak** on a 16GB computer, no automatic termination; no implied memory sufficiency without full system context. Produces a tightly scoped JSON report with model Small/Large, 2/4/6 threads, song duration, elapsed, notes count, checkpoint notifications/resume flag and measured process metrics, with no audio or personal file paths.
2. `desktop-preview/process-metrics.cjs`: exposes a read-only `snapshot()` on the existing Windows PID sampler. Snapshot exists while native inference is actually running and is displayed in heartbeat messages; the original `stop()` benchmark API stays backward-compatible.
3. `desktop-preview/main.cjs`: strictly validates the actual WAV header/data bytes before invoking the CLI. Starts process sampling once the child is launched. Every 15s it reports last **real** CLI progress, elapsed wall time, time since last PROGRESS/checkpoint signal, actual RAM/CPU or explicit missing-data state. 5-second native checkpoint writes count as real engine activity but NEVER advance the percent. On successful transcription, stores private aggregate `NOTIQ-Data/full-song-reports/notiq-5ne-<timestamp>-<model>-<threads>threads.json` beside the Windows portable EXE. Native output and previous MIDI remain independent of report write success. On cancelled/error runs, no success report is fabricated. Reports do not contain the recognized MIDI note events.
4. `desktop-preview/repack-5md.cjs`: includes `full-song-health.cjs` in rebuilt Electron `app.asar`, preventing a package that works in source but crashes at launch.
5. `desktop-preview/tests/full-song-5ne.test.cjs`: 6 actual Windows Node tests covering 4/6min Float32 WAV size/duration, rejection of truncated/non-16k input, no fabricated percent after a simulated 13-minute engine silence, slow-model and RAM/CPU displays (with high-memory warning), private report schema/validation, absent metrics not treated as a reading.
